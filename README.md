A high-performance, cache-optimized, multi-threaded **Static Timing Analysis (STA)** engine developed in modern C++20.

Grounded in **Chapter 8 of *VLSI Physical Design: From Graph Partitioning to Timing Closure*** (Kahng et al., 2nd ed.), this engine implements a **Data-Oriented Design (DOD)** architecture using a **Bidirectional Compressed Sparse Row (Bidir-CSR)** graph, full dual-mode (Setup and Hold) batch propagation, event-driven incremental timing updates with $\epsilon$-pruning, level-parallel task execution via **Taskflow**, and causal critical path extraction.

## Key Architectural & Systems Features

### 1. Pin-Centric Bidirectional CSR Graph (`TimingGraph`)
* **Pin-Level Granularity:** Nodes represent physical terminals (`PI`, `PO`, `INTERNAL`), not monolithic gates. Gate delays are modeled as internal **Cell Arcs** ($in \to out$), while interconnects are modeled as directed **Net Arcs** ($out \to in$). This natively handles multi-fanout nets ($1 \to N$) with independent RC wire delays without pin duplication.
* **Zero Pointer Chasing:** All adjacency data is stored in flat, parallel index arrays (`fwd_offsets`, `fwd_arcs`, `bwd_offsets`, `bwd_arcs`). Forward and backward neighbor queries return non-allocating, zero-overhead `std::span<const ArcID>` memory views.
* **Zero Dynamic Allocations in Sweeps:** Memory is pre-allocated upfront; hot traversal loops execute with zero heap allocations.

### 2. Topological Ordering & Levelization
* **Kahn's Generational Partitioning:** Leverages a FIFO queue (`std::queue<uint32_t>`) to naturally partition nodes into mathematically independent topological levels ($L_0, L_1, \dots, L_K$).
* **Cycle Detection:** Combinational feedback loops are detected during levelization, guaranteeing strict DAG invariants before numerical analysis runs.

### 3. Dual-Mode Batch Analysis (Setup & Hold)
* **Late Mode (Setup / Max Delay):**
  $$AT_{\text{late}}(v) = \max_{u \in \text{pred}(v)} \big( AT_{\text{late}}(u) + d_{\max}(u, v) \big)$$
  $$RAT_{\text{late}}(u) = \min_{w \in \text{succ}(u)} \big( RAT_{\text{late}}(w) - d_{\max}(u, w) \big)$$
  $$\text{Slack}_{\text{setup}}(v) = RAT_{\text{late}}(v) - AT_{\text{late}}(v)$$
* **Early Mode (Hold / Min Delay):**
  $$AT_{\text{early}}(v) = \min_{u \in \text{pred}(v)} \big( AT_{\text{early}}(u) + d_{\min}(u, v) \big)$$
  $$RAT_{\text{early}}(u) = \max_{w \in \text{succ}(u)} \big( RAT_{\text{early}}(w) - d_{\min}(u, w) \big)$$
  $$\text{Slack}_{\text{hold}}(v) = AT_{\text{early}}(v) - RAT_{\text{early}}(v)$$
* **IEEE-754 Boundary Sentinels:** Reductions use $\pm\infty$ (`std::numeric_limits<float>::infinity()`) to prevent arbitrary sentinel masking bugs.

### 4. Event-Driven Incremental STA Engine
* **Transitive Fanout / Fanin (TFO / TFI) Cones:** When an optimization tool modifies local arc delays ($d \to d'$), the engine re-evaluates only the affected downstream and upstream cones rather than sweeping the entire circuit.
* **Topological Priority Queues:**
    * Forward $AT$ propagation uses a **Min-Heap** (`levels_map[a] > levels_map[b]`) to ensure upstream inputs settle before multi-input gates evaluate.
    * Backward $RAT$ propagation uses a **Max-Heap** (`levels_map[a] < levels_map[b]`) to pull deadlines back in descending topological order.
* **$\epsilon$-Pruning:** Changes below $\Delta = 10^{-5}\text{f}$ are pruned immediately, terminating propagation along non-critical branches.

### 5. Multi-Core Concurrency via Taskflow
* **Concurrent Sweeps ($AAT \parallel RAT$):** Because forward $AT$ and backward $RAT$ operate on disjoint memory arrays, Taskflow executes both levelized pipelines concurrently in parallel branches before joining at the Slack calculation stage.
* **Data-Race Freedom by Construction:** Nodes within a topological level write only to their own array slot (`at[v]`), ensuring lock-free, race-free parallel execution validated under ThreadSanitizer (TSan).

## Empirical Benchmark Performance

* **CPU:** Intel Core i7-12650H (6 P-cores @ 4.7 GHz with SMT, 4 E-cores @ 3.5 GHz)
* **OS:** Linux Mint x86_64 | **Compiler:** Clang 16 (`-O3 -DNDEBUG`)
* **Harness:** Google Benchmark across the ISCAS85 benchmark suite

### 1. Sequential Scaling ($O(|V| + |E|)$ Linear Proof)

| Benchmark | Gate Count | Pin Count (V) | Topo Levels | Sequential Runtime | Normalized Cost / Pin |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`c17`** | 6 | 25 | 8 | **0.256 µs** | **10.2 ns / pin** |
| **`c432`** | 160 | 539 | 36 | **5.56 µs** | **10.3 ns / pin** |
| **`c880`** | 383 | 1,198 | 50 | **12.4 µs** | **10.4 ns / pin** |
| **`c3540`** | 1,669 | 4,680 | 96 | **51.5 µs** | **11.0 ns / pin** |
| **`c6288`** | 2,406 | 7,280 | 250 | **75.4 µs** | **10.4 ns / pin** |
| **`c7552`** | 3,512 | 9,971 | 88 | **102.0 µs** | **10.2 ns / pin** |


> **Key Takeaway:** As circuit size scales by $400\times$ (from 25 pins to nearly 10,000 pins), the engine maintains an amortized cost of **$\approx 10.3$ nanoseconds per pin**. Even on `c6288` (a 16-bit multiplier with an extreme depth of 250 pin-levels and 124,000+ paths), performance per pin does not degrade, confirming spatial and temporal cache locality.

### 2. Multi-Threaded Scaling on `c7552` (Amdahl's Law Analysis)

```text
--------------------------------------------------------------------------
Benchmark                                Time             CPU   Iterations
--------------------------------------------------------------------------
BENCHMARK_STA_SEQUENTIAL/c7552         102 us          102 us         6659
BENCHMARK_PARALLEL_STA_C7552/1         131 us         16.9 us        43568
BENCHMARK_PARALLEL_STA_C7552/2         130 us         18.7 us        37955
BENCHMARK_PARALLEL_STA_C7552/4         228 us         20.0 us        36156
BENCHMARK_PARALLEL_STA_C7552/6         344 us         24.1 us        10000
BENCHMARK_PARALLEL_STA_C7552/8         465 us         23.5 us        10000
BENCHMARK_PARALLEL_STA_C7552/12        766 us         25.4 us        10000
BENCHMARK_PARALLEL_STA_C7552/16       1028 us         24.0 us        10000
```

> **Amdahl's Law vs. Synchronization Latency:** On `c7552`, total sequential execution takes only $102\,\mu\text{s}$ across 88 levels ($\approx 1.16\,\mu\text{s}$ compute per level). Taskflow barrier synchronization across threads costs $\approx 1\text{--}2\,\mu\text{s}$ per barrier (176 total barriers forward and backward $\approx 264\,\mu\text{s}$ cumulative barrier latency). This empirically confirms that level-parallel sweeps on micro-circuits are dominated by barrier latency, whereas large industrial netlists ($>1\text{M}$ pins, where level compute is tens of milliseconds) amortize barrier overhead to achieve near-linear multi-core speedup.

## Building and Running

### Prerequisites
* **C++20 Compiler:** Clang 16+ or GCC 13+
* **Build Tools:** CMake 3.25+ and Ninja
* **Package Manager:** `vcpkg` (set via `CMAKE_TOOLCHAIN_FILE`)

### 1. Configure and Build (Release)
```bash
# Configure with presets
cmake --preset release

# Build all targets (library, CLI, tests, benchmarks)
cmake --build --preset release
```

### 2. Run the Unit Test Suite (with AddressSanitizer & UBSan)
```bash
# Configure and run under ASan / UBSan
cmake --preset debug-sanitizers
cmake --build --preset debug-sanitizers
ctest --preset debug-sanitizers --output-on-failure
```

### 3. Run Google Benchmark
```bash
./build/release/sta_benchmarks
```

### 4. Run the CLI Application
```bash
./build/release/sta_app
```

# vlsi-sta-engine

A high-performance, cache-optimized, multi-threaded Static Timing Analysis (STA) engine implemented in modern C++20.

The implementation is grounded in the theoretical foundations of Chapter 8 of "VLSI Physical Design: From Graph Partitioning to Timing Closure" (Kahng, Lienig, Markov, Hu). The engine is built using Data-Oriented Design (DOD) principles, featuring a Bidirectional Compressed Sparse Row (Bidir-CSR) timing graph, full dual-mode (Setup and Hold) batch propagation, event-driven incremental timing analysis with epsilon-pruning, level-parallel concurrency via Taskflow, and causal critical path extraction.

## 2. Core Architectural & Theoretical Foundations

### Pin-Centric Timing DAG Modeling
* **Pin-Level Granularity:** Graph vertices model physical circuit pins and primary I/O ports rather than monolithic logic gates. Logic gates are represented internally as collections of input and output pins linked by cell timing arcs.
* **Fanout Disambiguation:** Interconnect networks with multi-fanout (1-to-N) are modeled as distinct, directed wire arcs leaving a single driver pin and terminating at discrete load pins. This allows each physical interconnect branch to carry independent early and late RC delay characteristics without requiring pin duplication or graph restructuring.

### Bidirectional Compressed Sparse Row (Bidir-CSR) Layout
* **Cache Contiguity:** Adjacency relationships are flattened into contiguous index arrays rather than pointer-linked adjacency lists.
* **Symmetric Traversals:** Two paired CSR structures are maintained: Forward CSR for fanout traversal and Backward CSR for fanin traversal.
* **Non-Allocating Queries:** Neighbor and level traversals return contiguous non-owning memory spans. Hot analysis sweeps execute with zero dynamic heap allocations.

### Generational Topological Levelization
* **Kahn's Algorithm:** Nodes are levelized into mathematically independent horizontal buckets (Level 0 through Level K).
* **FIFO Generational Invariant:** Using a FIFO queue during in-degree reduction guarantees that nodes are popped in strictly non-decreasing level order. Nodes enter the queue strictly when their final predecessor resolves, ensuring contiguous level grouping directly from the traversal order.
* **Acyclic Validation:** Any combinational feedback loop prevents full in-degree reduction, enabling automated detection and rejection of cyclic circuits.

### Dual-Mode Timing Formulation

```text
Late Mode (Setup / Maximum Delay Analysis):
  Data Arrival Time:          AT_late(v)  = max over u in pred(v) of ( AT_late(u)  + d_max(u, v) )
  Data Required Arrival Time: RAT_late(u) = min over w in succ(u) of ( RAT_late(w) - d_max(u, w) )
  Setup Slack:                Slack_setup(v) = RAT_late(v) - AT_late(v)

Early Mode (Hold / Minimum Delay Analysis):
  Data Arrival Time:          AT_early(v)  = min over u in pred(v) of ( AT_early(u)  + d_min(u, v) )
  Data Required Arrival Time: RAT_early(u) = max over w in succ(u) of ( RAT_early(w) - d_min(u, w) )
  Hold Slack:                 Slack_hold(v) = AT_early(v) - RAT_early(v)
```

* **Boundary Sentinels:** Reductions initialize maximum operations with negative infinity and minimum operations with positive infinity using standard floating-point limits, eliminating sentinel masking errors across arbitrary delay ranges.

### Event-Driven Incremental Analysis
* **Cone of Influence:** Modifying local arc delays does not trigger a full graph re-evaluation. The engine isolates updates strictly to the Transitive Fanout (TFO) cone for arrival times and the Transitive Fanin (TFI) cone for required arrival times.
* **Topological Priority Ordering:**
  * Forward propagation uses a min-heap ordered by topological level to ensure that all upstream inputs feeding reconvergent logic settle before multi-input gates evaluate.
  * Backward propagation uses a max-heap ordered by topological level to pull timing deadlines upstream in descending order.
* **Epsilon-Pruning:** Signal changes smaller than a floating-point tolerance of 1e-5 are pruned immediately, preventing propagation down non-critical branches.

### Level-Parallel Concurrency (Taskflow)
* **Disjoint Sweeps:** Forward arrival time propagation and backward required arrival time propagation operate on completely disjoint memory buffers. The engine executes the entire forward level pipeline and the entire backward level pipeline concurrently in parallel branches.
* **Intra-Level Data Parallelism:** Within any given topological level, all pins have their dependencies fully resolved in prior levels. Nodes within a level are evaluated concurrently across worker threads with zero mutex contention.
* **Data-Parallel Slack Evaluation:** Once both sweeps terminate, slack calculation executes across all pins in parallel, joining into a final Worst Negative Slack reduction.

### Critical Path Extraction
* **Causal Backtracing:** Starting from the primary output exhibiting the worst negative slack, the engine traces backward along causal arcs satisfying the relationship where the predecessor arrival time plus the arc delay equals the current pin arrival time.
* **Path Reporting:** Traced pins and timing arcs are reversed to yield the critical path from startpoint to endpoint, reporting incremental delays, absolute arrival times, required deadlines, and slacks.

* **Environment:** Intel Core i7-12650H (6 Performance cores at 4.7 GHz, 4 Efficient cores at 3.5 GHz), Linux Mint x86_64, Clang 16 (-O3 -DNDEBUG)

* **Topological Depth Independence:** The c6288 benchmark features 250 pin-levels (a 16-bit multiplier with over 124,000 paths). The engine processes this deep structure at 10.4 ns per pin without performance degradation, confirming that the contiguous CSR buffers eliminate cache-line thrashing.

### Amdahl's Law and Synchronization Latency
* **Fine-Grained Barrier Contention:** In c7552, total sequential execution requires only 102 microseconds across 88 topological levels, yielding an average computational workload of approximately 1.16 microseconds per level.
* **Overhead Ratio:** Synchronizing worker threads across a task barrier in multi-threaded runtimes incurs an overhead of 1 to 2 microseconds per barrier. With 88 forward levels and 88 backward levels (176 total barriers per pass), cumulative barrier synchronization latency accounts for roughly 264 microseconds.
* **Workload Boundary:** On small netlists where per-level computation is in the low microsecond range, thread coordination latency exceeds computational payload as thread count increases. Level-parallel sweeps are designed for industrial-scale netlists (exceeding 100,000 to millions of pins), where per-level compute reaches tens of milliseconds and amortizes barrier latency to under 0.01 percent.

## 5. Building and Verification

### Prerequisites
* C++20 compliant compiler: Clang 16+ or GCC 13+
* CMake 3.25+ and Ninja build system
* vcpkg package manager for external dependencies

### Build Configuration (Release Mode)
```bash
cmake --preset release
cmake --build --preset release
```

### Run Test Suite (AddressSanitizer and UndefinedBehaviorSanitizer)
```bash
cmake --preset debug-sanitizers
cmake --build --preset debug-sanitizers
ctest --preset debug-sanitizers --output-on-failure
```

### Execute Google Benchmark Suite
```bash
./build/release/sta_benchmarks
```

### Execute the Standalone CLI Application
The CLI application accepts an optional benchmark netlist path and an optional target Required Arrival Time (RAT):

```bash
# Run on c17 with default constraints
./build/release/sta_app ../../iscas85/c17.bench

# Run on c432 with custom target deadline (50.0 ns -> TIMING MET)
./build/release/sta_app ../../iscas85/c432.bench 50.0

# Run on c432 with tight target deadline (40.0 ns -> TIMING VIOLATION)
./build/release/sta_app ../../iscas85/c432.bench 40.0
```
